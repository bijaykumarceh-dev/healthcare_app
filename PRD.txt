Product Requirements Document (PRD) – “SwasthSahay” (Flutter Healthcare App)
1. Product Overview
Product name: SwasthSahay
Vision: एक ऐसा secure, offline-first healthcare app जहाँ patient अपना treatment history और current diseases देख सके, doctor patients का timeline देखकर सही treatment दे सके, और user medicines व health products खरीद सके—सब कुछ encrypted और privacy-first तरीके से।
Target users:

Patients (general public)

Doctors (verified practitioners)

Shoppers (sirf products खरीदने वाले, medical record नहीं)

Platforms: Android + iOS (Flutter single codebase)

Key differentiator: Offline-first + encrypted local storage + simple patient timeline + doctor-friendly view, जो कम internet वाले areas में भी काम करे।

2. Goals & Success Metrics
2.1 Business Goals
Patient और doctor के बीच medical information gap कम करना।

Medicines और health products की discoverability बढ़ाना।

Trusted, secure health data platform बनाना।

2.2 User Goals
Patient:

आसानी से apni diseases, treatments, prescriptions timeline में देखना।

Medicines और products खरीदना।

Doctor:

Patients का पूरा medical history एक जगह देखना।

Quick prescriptions और notes add करना।

Shopper:

Products browse, search, order करना।

2.3 Success Metrics (MVP phase)
70%+ users का first session में successful signup + profile creation।

50%+ patients ने कम से कम 1 condition या treatment add किया।

60%+ doctors ने कम से कम 1 patient को prescription दिया।

Crash-free sessions > 95%।

Offline mode में data add करके online sync success rate > 90%।

4.4 Offline-First & Sync (Flutter Specific)
4.4.1 Local Storage
Tech choices (Flutter):

Local DB: Isar या Hive (fast, NoSQL, Flutter-friendly)

Encryption:

Sensitive tables (conditions, treatments, prescriptions) को AES-256 से encrypt

Keys को platform keystore (Android Keystore, iOS Keychain) में store

Secure storage plugin: flutter_secure_storage या local_auth + custom wrapper

Rules:

PHI (conditions, treatments, prescriptions, patient profile) हमेशा encrypted रहेगी।

Non-sensitive data (products, categories) को plain store किया जा सकता है।

4.4.2 Sync Architecture
Local schema additions:

हर record में:

sync_status: pending | synced | failed

server_id (nullable; backend se milne par fill)

last_synced_at (nullable)

Sync flow:

App start/connectivity change पर:

Check network status

If online → trigger sync

Push:

Local pending inserts/updates को batch में server भेजें

Pull:

Server se naye/updated records fetch कर local merge

Conflict resolution:

Default: “last-write-wins” based on updated_at

Doctor prescriptions > patient self-reported entries (priority rule)

Rules:

Offline mode में सभी CRUD operations local DB पर होंगे; UI को पता नहीं चलना चाहिए कि data abhi sync नहीं हुआ, सिवाय optional “Sync pending” indicator के।

Sync failures को retry queue में डाला जाएगा (exponential backoff)।

4.5 Security & Privacy Rules
General:

सारे network calls HTTPS (TLS 1.2+) over होंगे।

Backend में sensitive columns (disease_name, diagnosis_summary, prescriptions) encrypted रहेंगे (field-level encryption optional par recommended)।

Authentication & Authorization:

JWT access token (short expiry) + refresh token (long expiry)

Token को secure storage में रखें; clear on logout

Role-based UI:

Patient features sirf patient role को

Doctor features sirf doctor role को

Shopper features sabko, par medical records sirf patient/doctor को

Audit Logging:

Backend में audit_logs table:

user_id, role, action (view_condition, add_prescription, etc.)

resource_type, resource_id

timestamp, ip_address, device_info

Doctor द्वारा patient data access हर बार log होगा।

Privacy:

Push notifications में PHI नहीं भेजनी (no disease names, no medicine details)।

Analytics में PHI नहीं भेजना; anonymized events use करना।

5. Non-Functional Requirements
Performance:

App cold start < 3 seconds (mid-range Android)

Local queries (conditions/treatments list) < 300 ms

Reliability:

Offline mode में core features (view/add conditions, treatments, prescriptions) fully functional

Sync success rate > 90% within 5 minutes of going online

Security:

All PHI encrypted at rest (local + server)

No PHI in logs, analytics, or crash reports

Scalability (future):

Backend designed for horizontal scaling (stateless APIs, DB read replicas)

6.4 Sync Manager (High Level)
dart
class SyncManager {
  final LocalConditionRepo localConditionRepo;
  final RemotePatientRepo remotePatientRepo;
  final Connectivity connectivity;

  Future<void> syncAll() async {
    if (!await connectivity.isConnected) return;

    await Future.wait([
      syncConditions(),
      syncTreatments(),
      syncPrescriptions(),
    ]);
  }

  Future<void> syncConditions() async {
    final pending = await localConditionRepo.getPendingSync();
    for (final c in pending) {
      try {
        await remotePatientRepo.upsertCondition(c.toRemoteDto());
        await localConditionRepo.markSynced(c.id);
      } catch (_) {
        await localConditionRepo.markSyncFailed(c.id);
      }
    }

    final remoteConditions = await remotePatientRepo.getUpdatedConditionsSince(...);
    await localConditionRepo.mergeRemote(remoteConditions);
  }
}
Sync को app start, connectivity change, और periodic timer (e.g., every 15 minutes when app in foreground) पर trigger करें।

9. Risk & Mitigation
Risk: Encryption keys lose हो जाएँ (app reinstall, device change)

Mitigation: Keys को backend से derive करने का mechanism (advanced) या user को warning कि local data reinstall पर चला जाएगा।

Risk: Sync conflicts复杂 हो जाएँ

Mitigation: MVP में simple “last-write-wins” + doctor-prescription priority; complex rules को future में ले जाएँ।

Risk: Scope creep (bahut सारे features)

Mitigation: Strict MVP scope; shopping module को optional रखें।
